# 音声メモ・目標コーチ

プロジェクト `eng-empire-498517-c6`。Cloud Schedulerが日本時間の毎日23時30分に当日の音声処理と財務シミュレーションを直列実行し、翌朝6時40分に日次の選択と集中Job、金曜7時10分に週次レビューJobを起動します。Vertex AI Gemini Flashの最新候補で音声と計画を処理します。Colabは手動実行の入口です。

## 動作

- 共有Drive `0AJ3Tsl0Aj8RyUk9PVA` の直下にある音声が対象。Driveのアップロード日時を日本時間へ変換し、午前5時で区切った処理日に割り当てます。通常設定では**当日分だけ**を処理し、前日以前の音声は混ぜません。
- Whisperを使用せず、`config.json` の `model: "latest_flash"` からVertex AIのGemini Flash最新候補を選びます。`auto_discover_latest_flash` が有効な場合はVertex AIのモデル一覧からFlash系モデルを優先し、取得できない場合は `model_candidates` の先頭、つまり `gemini-flash-latest` から試します。Cloud Runと保存バケットは東京。モデル処理を日本国内に限定する構成ではありません。
- WAVのまま文字起こしでき、MP3への変換は不要です。15MBを超えるWAVは一時的にCloud Storageへ置き、GeminiにはGCS URIで渡した後に削除します。フィラーも残しますが、認識誤りを完全に防げるわけではありません。同じ名前のWAVとMP3はMP3を優先します。
- 文字起こしは日ごとにまとめ、普段使っているメインカレンダーに終日・予定ありにしないイベントとして更新。長文は全文をDriveに保存し、その1件からリンクします。元の文字起こしファイルは上書きしません。
- メインカレンダーの過去30日と未来7日、前日1日分の文字起こし、自己申告資産、設定目標を参照。助言は同じメインカレンダーの別の「今日のコーチ」終日イベントに保存します。自動作成した音声メモ・コーチ予定は、次回以降の予定文脈から除外します。
- 「今日は優しく」「今週は仕事優先」など明示した希望を助言に反映します。音声による方針指定の参照期間は30日です。
- 「今日のコーチ」は音声メモの質問・相談への一問一答を優先します。通常設定では前日1日分の文字起こしから質問を拾い、`Q1（録音日時）：原文の質問` → `A1：回答` の順に並べます。質問数は3件に制限せず、今日の行動提案だけを最大3件にします。原文は変更しません。外部検索は行わず、最新情報など確認できない内容は未確認と明示します。
- 預金・投資・借入を口座ごと・通貨ごとに記録。最新の自己申告値を使用し、残高を入金として加算しません。日付の異なる値の合算であることを明記し、通貨換算をしません。
- 音声に「銀行Aの預金残高は12万円、日本円」「証券Aの評価額は30万円、日本円」「ローンAの借入残高は5万円、日本円」のように、対象と通貨を明示してください。目標額や曖昧な金額は資産に加えません。同じ口座は同じ呼称を使ってください。


### 選択と集中エージェント

- Google Calendarを判断の中心にして、予定量・空き時間・TODOリスト予定・音声メモ・自己申告資産・Codex進捗イベントを総合します。
- Google Tasks APIで、全タスクリストの未完了タスクを毎日すべて読み込みます。完了済みタスクは金曜の週次レビューで前週分だけ読み、できなかった理由の確認に使います。
- 日次Jobは `今日の選択と集中 YYYY-MM-DD` と、必要な複数の `集中: ...` 予定をメインカレンダーに作成または更新します。
- 金曜Jobは `選択と集中レビュー YYYY-Www` を作成または更新し、翌週の方針、今週やらないこと、相談事項、収入を増やす行動を整理します。
- 元のGoogle Tasksは読み取り専用です。タスクのタイトル・本文・完了状態は変更しません。
- Calendarイベントにはアプリ所有情報を保存するため、同じ日・同じ週に再実行しても重複作成せず更新します。
- Codexの各タスク進捗はCloud Runから直接読めないため、Codex側の毎日スケジュールで `Codex進捗 YYYY-MM-DD` をCalendarへ登録し、選択と集中JobがそのCalendar文脈を読みます。

### エージェント台帳

| 名前 | 担当 | 主な入力 | 主な出力 |
|---|---|---|---|
| アーカ | 音声書記 | 当日分の音声ファイル | 忠実な文字起こし |
| ミラー | 一問一答コーチ | 文字起こし、予定、目標 | 今日のコーチ |
| ソーター | 思考Inbox整理 | 指定Google Doc、当日音声 | Google Tasks候補、保留理由 |
| コンパス | 日次の選択と集中 | Calendar、Tasks、思考、財務、Codex進捗 | 今日の主タスクと集中予定 |
| ルート | 週次航路設計 | 前週実績、未完了、翌週予定 | 週次レビュー |
| クロニクル | 月次行動分析 | 前月の予定、完了Tasks、思考、財務 | 月次レビュー、翌月重点3件 |
| キャッシュナビ | 財務試算 | `財務:` 予定、確定した音声取引 | 残高・安全支出上限・完済予測 |
| タワー | Codex進捗集約 | ピン留め中心のCodexタスク | `Codex進捗 YYYY-MM-DD` |
| スイーパー | 音声整理 | 保存・Calendar登録まで検証済みの音声 | Driveのゴミ箱への安全な移動 |

日次・週次・月次は同じ世界観を共有しますが、固定名と担当を分けています。名前は `config.json` の `agent_registry` を棚卸し台帳として管理します。

### 人財務シミュレーションAI

- 通常の予定・TODO・自由記述は財務台帳に取り込みません。タイトルが `財務:` で始まり、下記の固定形式を満たす予定だけを読みます。作成先は普段使っているメインカレンダーです。
- 種類は `残高`、`借入`、`収入`、`支出`、`返済`、`支払予定`、`訂正` です。`借入` は指定日の**現在の元本残高**として登録し、その日以後だけ年利を日次計上します。借入ごとの `年利` と予定返済が不足する場合は、完済日を出しません。
- 音声メモは、登録済みの前日分の「音声メモ YYYY-MM-DD」Calendarイベントを入力にします。前々日以前の出力を再解析せず、確定した取引は台帳に維持します。金額・JPY・口座名・日付が原文で確認できる収入、支出、返済、支払予定だけを抽出します。たとえば「現金で500円を支払った」「9月20日に普通預金から3000円を払う予定」のように記録します。実績は台帳と残高に反映し、予定の買い物は「買い物予定を含めた試算」にだけ反映します。生き金の判定は行動傾向用で、残高計算を変えません。
- 毎日 `財務シミュレーション YYYY-MM-DD` を更新します。現在残高、30日間の最低予測残高、安全支出上限、借入残高、完済予測、買い物予定の影響を表示します。実績が60日分に達すると、Ridge回帰の学習実験と時系列評価の誤差も併記します。実額による計算が常に基準です。
- Calendarの取得範囲は過去365日から未来365日までです。完済計算だけは最大3650日まで続けます。したがって、10年分の通常予定を読み込んだりGeminiへ渡したりしません。

初回に、確認済みの残高と借入ごとの元本・年利を次の形式で登録してください。金額や口座名は例なので、実際の値に置き換えます。

```text
タイトル: 財務: 残高
金額: 100000
通貨: JPY
口座: 普通預金
日付: 2026-09-14
状態: 実績
内容: 確認済み残高
```

```text
タイトル: 財務: 借入
金額: 300000
通貨: JPY
借入名: ローンA
年利: 15.0
日付: 2026-09-14
状態: 実績
内容: 現在の元本残高
```

返済は `口座` に借入名、`支払口座` に引落元を記入します。将来の請求は `財務: 支払予定` と `状態: 予定`、自分で予定する買い物は `財務: 支出` と `状態: 予定` で登録します。訂正は新しい `財務: 訂正` 予定に正しい値と、元の自動記録に表示される `取引ID` を `訂正対象` として書きます。元の記録は履歴として残ります。

## 手動認証と初回起動

1. PowerShellでこのフォルダを開き、`./deploy.ps1 -Stage Prepare` を実行します。
2. GCPのGoogle Auth Platformで同意画面を設定し、**デスクトップアプリ**のOAuthクライアントを作成します。外部アプリを「テスト」のままにすると、通常リフレッシュトークンが7日で期限切れになるため、継続運用では公開状態や組織内利用を適切に設定します。
3. 作成直後の画面でJSONをダウンロードし、手元に保管します。Googleの仕様上、シークレット全文を後から再取得できない場合があります。取得できない場合は同じクライアントにシークレットを追加して作成直後に保存するか、デスクトップ用クライアントを新規作成します。チャットへの貼り付けは不要です。
4. 次を実行し、対象のDriveとメインカレンダーを持つGoogleアカウントでブラウザ認証します。

```powershell
./.venv/Scripts/python.exe setup_oauth.py 'C:/実際の保存先/client_secret.json'
```

この処理はDrive読取・アプリ作成ファイルの保存・メインカレンダー予定の読取と書込・Google Tasksの読取とアプリ作成タスクの追加を承認します。認証情報は`voice-coach-oauth`という専用Secret Managerシークレットに直接保存します。既存のGmail用シークレットは使用しません。Tasks書込scopeを追加した後は、手動OAuth認証を1回やり直してください。

5. `config.json` の `goals` を設定します。例（自分の目標に置き換える）:

```json
"goals": [{"title": "ここに目標", "deadline": "2026-12-31", "current": "現在の状況", "target": "達成条件"}]
```

6. 設定をアップロードし、接続チェックを実行します。

```powershell
gcloud storage cp config.json gs://eng-empire-498517-c6-voice-coach/config.json --project=eng-empire-498517-c6
./.venv/Scripts/python.exe app.py --check --local-gcloud
./deploy.ps1 -Stage Deploy
gcloud run jobs execute voice-coach-daily --project=eng-empire-498517-c6 --region=asia-northeast1 --wait
gcloud run jobs execute voice-coach-finance --project=eng-empire-498517-c6 --region=asia-northeast1 --wait
gcloud run jobs execute voice-coach-daily-focus --project=eng-empire-498517-c6 --region=asia-northeast1 --wait
gcloud run jobs execute voice-coach-monthly-focus --project=eng-empire-498517-c6 --region=asia-northeast1 --wait
```

7. メインカレンダーの文字起こし・助言・財務シミュレーション・選択と集中イベントを確認後、毎日23時30分の音声＋財務処理、翌朝6時40分の日次focus、金曜7時10分の週次focusを有効にします。

```powershell
./deploy.ps1 -Stage EnableSchedule
```

## 運用

### 処理済み音声の自動削除

`./enable_audio_cleanup.ps1` を実行すると、GCPへのログイン、コードの配置、Drive変更権限の手動認証を順に行い、`trash_processed_audio` を有効にします。認証JSONは前回Downloadsに保存したものを使用します。Drive全体の変更権限がGoogleの承認画面に表示されますが、処理対象は設定済みフォルダ直下の音声に限定します。

文字起こし・分析・コーチ生成が成功し、GCSとDriveの全文保存、メインカレンダー登録を確認した音声だけゴミ箱へ移します。移動前にファイル名・所在・内容の版が変わっていないか再確認します。処理失敗・容量超過・当日の音声・未処理の重複形式・テキストは対象外です。未処理の重複形式は次回以降に処理し、同じ録音の文字起こしを更新します。ゴミ箱への移動が失敗した場合は次回再試行します。

処理済みと確認できる古い音声は、文字起こし対象の日数設定とは別にゴミ箱移動の候補になります。対象は状態保存、文字起こし、当日のコーチ出力、Calendar登録のすべてが確認できるものだけです。既存のDrive全文保存がこのアプリから更新できない場合は、新しいアプリ専用の保存ファイルを作成し、古い履歴は上書きしません。

ゴミ箱内のファイルは通常30日後にGoogleによって完全削除されます。自動削除を止めるにはGCSの設定で `trash_processed_audio` を `false` にします。

既存の文字起こしは `import_existing_transcript.py FILE_ID` で一度だけ取り込めます。指定フォルダ内のテキストが対象で、`■ YYYY-MM-DD_HH-MM-SS.mp3` 等の見出しから録音日を判定します。同名録音は重複追加しません。後日、同じ録音の音声原本が入るとGeminiによる文字起こしへ置き換えます。

新しい音声はGoogle Driveのアップロード日時を日本時間へ変換し、午前5時を1日の境界として分類します。たとえば9月16日05:00以上、9月17日05:00未満のアップロードは9月17日分です。文字起こし内の表示名は `2026-09-17_04-59-59_upload-ファイルID先頭8文字.m4a` の形式にし、元のDrive名も状態記録へ残します。日次ジョブは境界が閉じた後の05:10に当日分を処理します。

同じDriveフォルダにある設定済みのGoogle Docは思考Inboxとして06:40の日次フォーカス処理で読みます。文書は編集せず、段落ハッシュで追加・変更を検出します。全候補を評価したうえで、主タスク1件と補助タスク最大2件だけを`マイタスク`へ追加し、残りは理由付きで保留します。毎月1日06:20には前月の確認済み行動を分析し、`選択と集中 月次レビュー YYYY-MM`を作成します。

`config.json`はGCSから毎回読み込みます。目標やモデル候補等の変更後は再アップロードします。`gemini-flash-latest` はGoogleの最新Flashエイリアスとして扱われます。必要に応じて、特定の新モデル名を `model_candidates` の先頭に追加すればコード再デプロイなしで追従できます。目標が空なら助言に未設定と表示します。手動再実行と定期実行は同じ処理・保存先です。

### 選択と集中エージェントの判断範囲

日次・週次とも、設定した2つのGoogle Calendarから、1日内に複数ある予定を含めてページ送りで全件取得します。日次は直近7日間の実績と90日先までの予定を読み、各予定を「今日・直近（3日以内）・短期（21日以内）・中期（90日以内）」に分けて判断します。Google Tasksは全リストの未完了と完了履歴を読むため、完了済みは再実行候補ではなく、継続できた行動や未達の傾向を判断する根拠になります。

カレンダーの`今日の選択と集中 YYYY-MM-DD`には、重要度の判定と「優先度を下げる候補」を理由・再検討条件とともに残します。候補はGoogle Tasksから削除・完了・変更されません。締切、外部との約束、収入への寄与、他の仕事を進める効果、生活維持を基準に判断します。

### 自律学習型AIエージェント「コンパス」

コンパスは、ユーザーの価値観を決める代行者ではなく、予定・タスク・完了履歴から仮説を育てるナビゲーターです。毎日「観測→仮説→一点の実験→翌日の検証」を行い、学習ログとして観測、根拠付きの仮説、当面のルール、次の実験を残します。この学習プロフィールは翌日以降の判断に渡されます。仮説は事実として扱わず、根拠が弱いものは相談事項として残します。

長期目標は「ソロプレナーになる」です。コンパスは、目先の空き時間だけでなく、顧客価値、収益機会、再現性のある仕組み、自律性を育てるかで短期・中期の選択を判断します。数値目標、顧客像、事業領域は未設定のため、根拠なく作りません。

失敗した音声は次回再試行し、成功済みの文字起こしは再利用します。不完全な文字起こしがあればその回の助言生成を延期してジョブを失敗にします。APIエラーの本文や個人の文字起こしをCloud Loggingに出しません。

1ファイル15MB・1回100ファイルの初期上限です。超過時は黙って省略せず失敗として扱います。長い録音は分割してください。実行ログはCloud Run Jobsの実行履歴から確認できます。音声が増えるとAPIと保存の従量料金が増えます。実音声での利用量を確認してGCP予算通知を設定してください。

突然の強制終了で`run.lock`が残った場合は、実行中ジョブがないことを確認してからバケット内のそのオブジェクトだけ削除してください。自動でロックを奪う処理はありません。

停止するにはCloud Schedulerの`voice-coach-0600`（05時10分実行）、`voice-coach-monthly-focus-0620`、`voice-coach-focus-0640`、`voice-coach-weekly-focus-friday`を一時停止します。音声のゴミ箱移動は上記の設定で制御します。文字起こしや助言の自動削除、予定招待、手入力Google Tasksの変更、銀行口座接続、投資売買はありません。
